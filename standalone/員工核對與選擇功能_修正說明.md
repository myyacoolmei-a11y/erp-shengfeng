# 晟風 ERP｜員工核對與出勤／薪資人員選擇修正

## 修正

1. 「員工管理」重複人員旁新增「核對資料」，可檢查每筆舊員工 ID，選擇今後作為出勤與薪資設定的主要 ID，按「確認並儲存」。確認過後會改為「已核對」，不再只顯示沒有動作的警示文字。
2. 重要：核對只指定主要 ID，**沒有刪除或搬移舊派工、績效、歷史出勤或薪資**。發現兩個 ID 已有歷史金額／出勤時，請先人工確認，不能假設歷史已真正合併。
3. 「出勤登記」、「薪資設定」、「薪資結算」的人員選擇改用直接可操作的原生下拉欄位，避免彈出選單被版面遮住。
4. 出勤／薪資人員選單共用後端以姓名＋非空電話辨識的一人一筆名單，若已核對則使用指定的主要員工 ID。沒有電話的不同記錄不自動合併。
5. 如果 API／資料庫未就緒，畫面會直接顯示讀取失敗原因，不再默默顯示空名單。

## 部署安全注意

- **務必先備份正式 PostgreSQL 資料庫**。只覆蓋前端不能修正尚未建表的資料庫。
- 本次在原本 `scripts/db-migrate-attendance-payroll.sql` 增加 `employee_identity_reviews` 資料表；此 migration 為 `CREATE TABLE IF NOT EXISTS`，可在原有出勤薪資資料表已存在的情況下再執行。
- 透過擁有 `DATABASE_URL` 的受控執行環境，在 `standalone` 目錄執行 `node scripts/db-migrate-attendance-payroll.mjs`，確認成功後再讓新的前後端程式投入使用；不可把 DATABASE_URL 貼到聊天或 GitHub。
- 先在 GitHub Desktop 測試分支核對差異與執行 typecheck、build，測試成功才合併到正式 main。未經驗證勿直接覆蓋線上服務。
- 未加入自動合併舊員工資料的功能，是為避免錯誤搬移或遺失既有派工／薪資／績效的歷史紀錄。
